# AGENTS.md — BraceKit

Chrome extension (Manifest V3) that reads the current page and chats with multiple LLM providers. Runtime is **Bun**; UI is React 19 + Zustand + Tailwind 4.

## Commands

```bash
bun install            # install deps
bun run dev            # watch + build to dist/, injects hot-reload.js, serves ws://localhost:35729
bun run typecheck      # = tsc --noEmit
bun run build          # = build.ts && tsc --noEmit (production build, minified)
bun test               # test runner
```

- There is **no `npm test`/`yarn test` script** — always use `bun test` (CI does the same).
- Load the extension from `dist/` (not root) at `chrome://extensions` with Developer mode on. `dist/` and `out/` are gitignored.
- Handle errors from APIs; Bun's build output is verbose.

## Build system (keep lists in sync)

Both `build.ts` and `dev.ts` re-implement the same pipeline independently: entrypoints, static-copy list, and the "flatten" arrays. They also read the root `manifest.json` and `public/*.html`. **When adding a page/script, update BOTH files** so lists match, plus `manifest.json` (e.g. `sandbox.pages`) and the HTML shell in `public/`. Bun emits `dist/src/*` and `dist/background/index.js`; these get flattened to `dist/*.js` and `dist/background.js` (sourcemaps only in dev). `chrome` is marked external in both.

`dev.ts` watches `./src`, `./public`, `./manifest.json`, `./mcp.js`.

## Typecheck scope (easy to miss)

`tsconfig.json` only covers `src/**/*`, `build.ts`, `tests/providers.test.ts`, `tests/index.test.ts`. **Tests under `tests/utils`, `tests/services`, `tests/store`, etc. run via `bun test` but are NOT typechecked by `tsc`.** Keep their types clean anyway.

Compiler is strict with `noUnusedLocals`/`noUnusedParameters`. Notable consequence: with Zustand use `set(() => ...)`, not `set((state) => ...)`, when the updater doesn't read state — the unused `state` param fails tsc (TS6133).

## Architecture

- `src/background/` service worker; `src/content.ts` content script (isolated world); `src/google-docs-bridge.ts` runs in the **MAIN world** on Google Docs only (see manifest).
- Web-visible pages: `src/index.tsx` (sidebar), `src/tab.tsx`, `src/onboarding.tsx`, plus `src/slide-renderer.ts`.
- Zustand stores: main `src/store/index.ts` (`useStore`) and a separate `src/store/slideStore.ts` (`useSlideStore`) — hydrate the latter via `setActiveProjectData(...)`.
- Types: `src/types/index.ts` is a giant barrel; add a new feature type in a dedicated module (e.g. `slides.ts`) and re-export from the barrel.
- `chrome.*` APIs exist only via `@types/chrome`. Sandboxed pages (opaque origin) have **no `chrome.*` access** — they communicate via `window.parent.postMessage` / parent listens on `iframe.contentWindow`.

- Phase runners live in `src/services/slidePhases.ts` (`runPlanPhase` + `runBuildPhase` + `runEditPhase`). New phase runners should copy this pattern. A plan session is approval-ready (`plan_ready`) when it calls `submit_plan` OR both `/brief.md` + `/design.md` exist non-empty (`hasValidPlanFiles`), and never auto-starts build. The **build** (US-020) and **edit** (US-023) runners have no `ask`/`submit_plan`, resolve `ready` when `rebuildDeckProjection(files).slideOrder.length > 0` (edit `done` if none), and MUST inject the approved plan docs into their system prompt (`composePlanDocsSystemPrompt`) since the isolated sub-agent has no main-chat history. ## Testing quirks

- Import `beforeEach` (and co) from `bun:test` explicitly — it is not a global.
- IndexedDB (`slideDB`, `conversationDB`, etc.) tests need `fake-indexeddb/auto`; reset the shared DB in `beforeEach`/`afterAll` (e.g. `clearAllSlideProjects()`).
- Write IndexedDB records resolving on `tx.oncomplete`, not `request.onsuccess`, or reads opened right after can get stale data. Return `IDBRequest<any>` from op callbacks (DOM lib's `onerror` this-type is invariant).
- `bun test`'s summary line hides failures — read the `(fail) ...` lines printed above the final `N pass / N fail` line.
- Chrome API mocks live in `tests/helpers/` (`createMockChrome`, etc.).
